# Fast-BOCPD Benchmarks

Performance benchmarking suite for Fast-BOCPD.

## Quick Start

### Run All Benchmarks (Easiest)

```bash
# From benchmarks/ directory
./benchmark.sh
```

This will:
1. Check for required data files
2. Generate missing datasets automatically
3. Run benchmarks on all dataset sizes
4. Display online vs batch performance comparison

### Manual Benchmark

```bash
cd scripts

# Run all datasets (1k, 10k, 100k)
python test_uv_gaussian.py

# Run specific size only
python test_uv_gaussian.py --size 10000

# More rigorous (20 runs instead of 10)
python test_uv_gaussian.py --runs 20 --warmup 3

# Test different lambda value
python test_uv_gaussian.py --lambda 200
```

## What Gets Benchmarked

### Online vs Batch Mode

The benchmark tests **both** modes to reveal Python overhead:

- **Online mode**: Processes observations one-by-one (real-time use case)
- **Batch mode**: Processes entire dataset at once (offline analysis)

**Batch is typically 1.2-2x faster** due to reduced Python loop overhead.

### Dataset Sizes

Three sizes test different performance characteristics:

| Size | Observations | Tests |
|------|--------------|-------|
| 1k   | 1,000        | Small dataset, initialization overhead |
| 10k  | 10,000       | Medium dataset, typical use case |
| 100k | 100,000      | Large dataset, scaling behavior |

### Metrics Reported

- **Median time**: Most robust timing metric (immune to outliers)
- **Throughput**: Observations processed per second
- **CV% (Coefficient of Variation)**: Measurement consistency (<5% is ideal)

## Generating Data

Data is auto-generated by `benchmark.sh`, but you can manually create datasets:

```bash
cd scripts

# Generate specific size
python generate_data.py uv gaussian 10000 150
#                       ^  ^        ^     ^
#                       |  |        |     segment length
#                       |  |        number of observations
#                       |  distribution type
#                       univariate

# Generate all standard sizes
python generate_data.py uv gaussian 1000 150
python generate_data.py uv gaussian 10000 150
python generate_data.py uv gaussian 100000 150
```

**Data characteristics:**
- Reproducible (fixed random seed)
- Shifting means: 0, 5, 10, ..., 40, 0, ... (cycles every 9 segments)
- Random variance per segment (0.5 to 2.5)
- Expected segment length: 150 observations


## Understanding Results

### Good Performance Indicators

**Low CV% (<5%)**: Consistent, reliable measurements  
**Stable throughput**: Similar obs/sec across dataset sizes  
**Near-linear scaling**: 10x data → ~10x time  
**Batch speedup 1.2-2x**: Expected Python overhead  

### Warning Signs

**High CV% (>10%)**: Unreliable measurements (OS interference, GC, etc.)  
**Decreasing throughput**: Algorithm doesn't scale well  
**Non-linear scaling**: 10x data → 20x+ time (algorithmic issue)


## Tips for Reliable Benchmarks

1. **Close other programs**: Minimize background CPU usage
2. **Use AC power**: Laptop power management affects performance
3. **Consistent environment**: Same Python version, NumPy, etc.
4. **Multiple runs**: Use `--runs 20` for production measurements
5. **Check CV%**: High variance means unreliable results
6. **Git track baselines**: Keep history of performance over time

## Troubleshooting

### High Variability (CV% > 10%)

**Problem**: Inconsistent timing measurements

**Solutions**:
- Close browser, IDEs, and other programs
- Increase `--runs` to 20 or 30
- Check system load with `htop`
- Disable CPU frequency scaling

### Data Files Not Found

**Problem**: `ERROR: data_uv_gaussian_n*.npy not found`

**Solution**:
```bash
cd scripts
python generate_data.py uv gaussian <n> 150
```

Or just run `./benchmark.sh` which generates automatically.

### Slow Performance

**Problem**: Throughput much lower than expected

**Check**:
- Correct Python interpreter (CPython, not PyPy)
- NumPy BLAS backend (`python -c "import numpy; numpy.show_config()"`)
- Debug vs Release build of C extension
- Compiler optimization flags in `setup.py`
